# План разработки прототипа: 3 части параллельно

Сценарий и эффекты описаны в [../06_final/final_plan.md](../06_final/final_plan.md) (разделы 3 и 4). API каркаса и правила по файлам — в [README.md](README.md). Этот файл объясняет, **в каком порядке** каждая часть работает и **по каким критериям** её работа считается готовой.

---

## 0. Обязательно для всех трёх: скилл моушн-дизайна

**Перед первой строкой анимации каждый Claude вызывает скилл моушн-дизайна (motion design skill) через инструмент Skill** и строит все анимации своей части по его правилам: тайминги, кривые, хореография, отклик на касание, reduced motion.

- Скилл вызывается на этапе 2, до написания любого `@keyframes`, `transition` или `requestAnimationFrame`.
- Если скилла нет в списке доступных, **не продолжай без него**: остановись и попроси пользователя установить скилл или назвать его точное имя.
- В итоге работы напиши, какие правила из скилла применил и к каким эффектам.

Если правила скилла противоречат этому плану, скилл главнее по вопросам **как анимировать** (тайминги, кривые). План главнее по вопросам **что анимировать** (какие эффекты на каком экране).

---

## 1. Общие правила движения (до вызова скилла и вместе с ним)

| Правило | Значение |
|---|---|
| Что анимируем | Только `transform` и `opacity` (плюс `stroke-dashoffset` для колец) |
| Длительность | Отклик на тап 80–150 мс, переход 250–320 мс, «вау»-момент не дольше 1,5 с |
| Кривые | Появление и вылет: `var(--ease-spring)`; уход и сдвиг: `var(--ease-out)`. Линейная кривая только у таймера |
| Пропуск | Любой эффект длиннее 600 мс пропускается тапом по экрану и сразу показывает итоговое состояние |
| Хореография | Элементы появляются по очереди с шагом 60–120 мс, главный элемент первым, кнопка «дальше» последней |
| Reduced motion | Если `FX.reduced`, то без движения, тряски и конфетти, только появление за 150 мс |
| Тактильность | `FX.vibrate` только на ключевых моментах: открытие сундука, level up, уведомление |
| Звук | `FX.sound` только после первого тапа, не чаще одного звука на действие |
| Производительность | 60 кадров/с на среднем Android: не больше 150 частиц, без `box-shadow` и `filter` в анимации, `will-change` только на время эффекта |

## 2. Этапы для каждой части

Все три части идут по одним и тем же этапам и в одно время, поэтому в контрольных точках их можно сливать.

| Этап | Время | Что делаем | Контрольная точка |
|---|---|---|---|
| 1. Статика | 0:00–0:40 | Вёрстка экранов без анимаций, логика, данные, переходы `go()` | Путь своей части проходится с телефона, состояние пишется в `State` |
| 2. Моушн | 0:40–1:40 | **Вызвать скилл моушн-дизайна**, сделать эффекты по списку ниже в порядке приоритета | Главные «вау»-эффекты (★) работают |
| 3. Полировка | 1:40–2:10 | Пропуск тапом, reduced motion, 375px и 430px, iPhone и Android, консоль без ошибок | Чек-лист части закрыт |
| 4. Сдача | 2:10–2:20 | Коммит в свою ветку, итог: что сделано, какие правила скилла применены, что нужно от общего каркаса | Ветка готова к слиянию |

Если время поджимает: этап 2 делаем только по ★, остальное оставляем статичным. Статичный экран, который работает, лучше анимированного, который ломается.

## 3. Часть 1 — Польза: S0, S1, S2, фон

**Файлы:** `js/part1.js`, `css/part1.css`, `data/profiles.js`. Ветка `proto-part1`.

**Этап 1. Статика**
1. S0: три группы чипов (класс, цель, направление), кнопка «Готово» неактивна, пока не выбраны все три. `State.set({answers, profileId})`.
2. S1: экран со списком строк и счётчиками, через 2,5 с `go('s2')`.
3. S2: сундук, подпись «Открой свой результат», после тапа карточка профессии, 2 полосы профессий, 3 вуза, 4-й вуз под замком, кольцо шанса на грант, 2 рычага, подпись «пример», кнопка → `s3`.
4. `data/profiles.js`: профили `med` и `biz` по образцу `it`.

**Этап 2. Моушн (сначала вызвать скилл)**
| Приоритет | Эффект | Ориентир |
|---|---|---|
| ★ | Открытие сундука: тряска в ожидании, тап → `FX.flash()`, вибрация, звук `ding`, лучи `conic-gradient` крутятся, карточка вылетает с пружиной и переворачивается `rotateY` | до 1,2 с |
| ★ | Кольцо шанса на грант: `stroke-dashoffset` и `FX.countUp` одновременно, лаймовое свечение в конце | 1,2 с |
| ★ | Сканер S1: 25–30 кружков-вузов слетаются с краёв в центр, луч сканера, бегущие счётчики | 2,5 с |
| ● | Полосы профессий растут от 0 с шагом 120 мс | 0,6 с |
| ● | Чипы S0: нажатие проседает, выбранный чип «впрыгивает» | 150 мс |
| ○ | Фон `#bg`: звёзды с медленным параллаксом, пауза при скрытой вкладке | постоянно |

**Готово, когда:** путь S0 → S2 → S3 работает на 375px, сундук открывается с первого тапа, повторный вход в S2 снова показывает закрытый сундук, консоль чистая.

## 4. Часть 2 — Действие и награда: S3, S4, S5

**Файлы:** `js/part2.js`, `css/part2.css`, `data/questions.js`. Ветка `proto-part2`.
Для проверки без части 1: `State.set({answers:{grade:'11',goal:'ent',field:'it'}, profileId:'it'}); go('s3')`.

**Этап 1. Статика**
1. S3: заголовок, большая кнопка `.btn-lime` «Первый шаг за 60 секунд», полоса плана 12% с 7 шагами, свёрнутый блок «Все возможности».
2. S4: 3 вопроса из `QUESTIONS[answers.goal]`, таймер на 60 с, проверка ответа, объяснение, счёт верных. Для `unknown` мини-профтест без правильных ответов. По истечении таймера переход дальше.
3. S5: итог «X из 3, твой уровень: …», бейдж, серия, неделя Пн–Вс, план 12% → 25%, замок на 4-м вузе. `State.set({streak:1, lastActive, plan:25, badge5min:true, challenge})`. Кнопка → `s6`.
4. `data/questions.js`: по 3 вопроса для `ent`, `sat`, `ielts` и 3 для `unknown`.

**Этап 2. Моушн (сначала вызвать скилл)**
| Приоритет | Эффект | Ориентир |
|---|---|---|
| ★ | Level up на S5: затемнение, бейдж вылетает в центр с 3D-переворотом, `FX.confetti()`, звук `levelup`, «Уровень 2» | до 1,5 с |
| ★ | Серия: огонь появляется с пружиной, цифра 0 → 1 переворачивается, загорается сегодняшний день | 1,2 с |
| ★ | Ответ в S4: верный — зелёный и `HUD.flyXP(кнопка, 10)`; неверный — красный и `FX.shake` | 0,3–0,6 с |
| ● | «×2 КОМБО» влетает при 2 верных подряд | 0,5 с |
| ● | Таймер: последние 10 с полоса краснеет и пульсирует | 10 с |
| ● | Кнопка S3 дышит (scale 1 → 1,04 раз в 2 с), по ней бежит блик | постоянно |
| ○ | Замок на 4-м вузе подрагивает раз в 3 с; полоса плана анимированно растёт до 25% | 0,5 с |

**Готово, когда:** путь S3 → S6 работает на 375px, повторный вход в S4 начинает вызов заново, таймеры останавливаются в `leave`, XP после вызова даёт уровень 2, консоль чистая.

## 5. Часть 3 — Возврат и демо: S6, S7, демо-меню, бот, деплой

**Файлы:** `js/part3.js`, `css/part3.css`, `api/notify.js`, `vercel.json`, `DEPLOY.md`. Ветка `proto-part3`.
Для проверки без частей 1–2: `State.set({answers:{goal:'ent',field:'it'}, profileId:'it', streak:1, xp:110, level:2, plan:25}); go('s6')`.

**Этап 1. Статика**
1. S6: 3 переключателя (Telegram, WhatsApp с маской +7, почта), время 19:00, пузырь предпросмотра, который меняется вместе с выбором. `State.set({notify})`. Кнопка → `s7`.
2. `api/notify.js`: только POST, текст до 300 символов, токен и chat_id только из `process.env.TG_BOT_TOKEN` и `process.env.TG_CHAT_ID`. Без переменных отвечает понятной ошибкой, а экран показывает предпросмотр.
3. S7: часы, уведомление, серия 1 → 2, вуз открывается, `State.set({streak:2, lockedUni:false, tomorrow:true})`, кнопка «Начать заново» → `State.reset()`.
4. Демо-меню по событию `demo:menu`: «Сбросить демо», «Перейти в Завтра», «Пропустить анкету», «Закрыть».
5. `DEPLOY.md`: Vercel, Root Directory = `07_prototype`, переменные окружения, как проверить бота.

**Этап 2. Моушн (сначала вызвать скилл)**
| Приоритет | Эффект | Ориентир |
|---|---|---|
| ★ | Перемотка времени в S7: стрелки делают полный круг, экран темнеет как вечером, подпись «Завтра, 19:00» | 1,2 с |
| ★ | Уведомление в стиле iOS падает сверху с пружиной, вибрация, звук `pop` | 0,5 с |
| ★ | Замок разлетается на 8 осколков, вуз открывается, серия 1 → 2 с переворотом цифры | 0,8 с |
| ● | Ответ бота: галочка «Venti написал тебе в Telegram» появляется с пружиной | 0,4 с |
| ● | Демо-меню выезжает снизу шторкой | 0,28 с |
| ○ | Переключатели S6 щёлкают с пружиной, пузырь предпросмотра плавно меняет текст | 150 мс |

**Готово, когда:** путь S6 → S7 → сброс → S0 работает на 375px, демо-меню открывается тройным тапом по логотипу, без переменных окружения ничего не ломается, консоль чистая.

## 6. Слияние и общая проверка

1. Ветки сливаются в `main` в любом порядке: файлы не пересекаются.
2. После слияния всех трёх один человек проходит путь S0 → S7 → сброс трижды подряд на iPhone и Android.
3. Проверяем стыки частей: S2 → S3 (профиль доходит до замка в S5), S5 → S6 (серия и XP видны в шапке), S7 → S0 (сброс очищает всё).
4. Включаем на телефоне «Уменьшить движение» и проходим путь ещё раз.
5. Деплой на Vercel по `DEPLOY.md`, проверка ссылки с чужого телефона, QR на последний слайд.
6. В 15:00 заморозка: дальше только исправление ошибок.
